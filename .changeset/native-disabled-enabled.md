React Native: `&:disabled` and `&:enabled` work on iOS and Android. Each element follows its own rule for "disabled": `Pressable` and custom components read the `disabled` prop, the Touchables, `Text` and `Switch` also honor the fallbacks React Native itself reads (`aria-disabled` on `TouchableOpacity` and `Text`, `accessibilityState.disabled` on the Touchables, on `Text`, and on `Switch` on Android), and `TextInput` reads `disabled` or `aria-disabled`. A component of your own that shares a React Native name, such as a design system's `Button`, follows the custom-component rule. Props set through `.attrs()` count; a prop that `shouldForwardProp` drops does not. `&:enabled` matches every element that is not disabled, including `View` and `Text`. A `transition` does not animate a change between the two; the values switch at once. On the web, `Pressable`, the Touchables, `Switch`, `Text` and `TextInput` match the same way from `disabled`; an element whose rendered HTML carries `aria-disabled="true"` also matches `&:disabled` (`Pressable` sets that attribute from `disabled`, so it matches only when disabled), and `accessibilityState.disabled` does not. See https://styled-components.com/docs/compatibility.
